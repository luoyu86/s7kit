# S7 自建服务器工具包（s7kit）

把斐讯S7体脂秤从"派健康云"解放到你自己的服务器：
复现APP的配网协议（ESPTouch + UDP握手），但把**你的服务器地址**写进秤，
再由本地服务器接收秤的上传数据。

依据：派健康 v3.0.1401 脱壳逆向（详见 ../S7分析报告.md）。

## 文件

| 文件 | 作用 |
|------|------|
| `s7_server.py` | 本地数据服务器：TCP监听，全量抓包+hex日志+启发式解码 |
| `s7_provision.py` | 配网脚本：ESPTouch广播 → 收秤宣告 → 注入你的服务器地址 |

## 网络要求（重要）

- **配网脚本必须跑在连接目标 WiFi 的机器上**（笔记本连 2.4G WiFi / 树莓派），
  因为 ESPTouch 靠 WiFi 空口包长度编码传密码；台式机网线口发不出去。
- WiFi 必须是 **2.4GHz**（S7 的 ESP 模块不支持 5G）。
- 服务器（`s7_server.py`）可以跑在同一台机器；给该机器设置**静态IP/DHCP保留**，
  否则路由器重启后IP一变，秤就连不上了。
- Windows 防火墙：放行 Python 的 **专用网络** 入站 UDP 7551-7553 和 TCP 8899。

## 步骤

### 第0步（可选，强烈建议先做）：旁听验证

想先确认秤的宣告帧能被收到（以及官方APP配网时的流量长什么样）：

```
python s7_provision.py --monitor-only
```

然后用官方派健康APP走一遍配网 —— 你会看到：
- 秤连上WiFi后发来的 `cmd=0x10` 宣告帧（产品=S7、MAC、CRC OK）
- 官方APP注入服务器时秤回的 `cmd=0x20`

都能看到 → 网络环境OK，继续下一步。

### 第1步：起服务器（先固定IP）

```
# 在将作为"秤的云"的机器上（例：192.168.31.50）
python s7_server.py --port 8899 --log s7_capture.log
```

### 第2步：重置秤进入配网模式

S7 恢复配网：拆下电池盖，**短按重置键**（或按说明书方式重置WiFi），
此时秤开始等待 SmartConfig。保持秤通电、离路由器近一点。

### 第3步：配网 + 注入你的服务器

```
# 在连着该WiFi的机器上
python s7_provision.py --ssid 你的WiFi名 --pass 你的WiFi密码 \
    --server-ip 192.168.31.50 --server-port 8899
```

流程输出依次为：
1. `ESPTouch 广播启动` —— 秤在配网模式会解析密码并连WiFi；
2. `[<] ... 宣告帧 cmd=0x10(已连上路由器) 产品=S7 MAC=...` —— 秤找到了；
3. `开始注入你的服务器地址 (UDP -> 秤:7550 x10)`；
4. `[OK] 秤已连上你的服务器`（同时 s7_server 控制台出现 `秤已连接: ...`）。

### 第4步：称重抓数据

站上秤称一次，`s7_server` 会立刻打出秤上传的原始字节并写入 `s7_capture.log`。
**把日志发给我，我来解协议**（帧结构大概率仍是 XOR 0x55 + CRC16 那套，参考
S9蓝牙协议还可能是 0xDB 帧）。解码完成后即可出"真正解析数据"的版本。

## 常见问题

| 现象 | 处理 |
|------|------|
| 3分钟收不到 0x10 | 秤没进配网模式 / WiFi是5G / 防火墙拦UDP / 换 `--no-broadcast` 反向试 |
| 收到0x10但一直无0x20、服务器也无连接 | 秤可能校验了服务器：抓 `s7_capture.log` 看；或秤固件TLS(概率低) |
| 服务器有连接但立刻断开 | 把 s7_server 控制台首包hex发我，可能是等服务端握手 |
| 想回到官方APP | 重新用派健康APP配网一次即可，秤会被写回官方服务器 |
| S7PE 用户 | S7PE走的是FlyLink配网不是ESPTouch，本脚本不适用 |
